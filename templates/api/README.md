# __APP_NAME__

A Tesl web service with a **PostgreSQL-backed entity**, signed-session auth,
request-body validation, an output proof, and unit tests. Generated by
`tesl init` from the `api` template.

## Files

| file        | what it is |
|-------------|------------|
| `app.tesl`  | the application: a `Todo` entity, two routes, two proofs, two `test` blocks |
| `tesl.toml` | the project manifest (`[database].mode = "managed"`, `TESL_POSTGRES_*` env) |

## The two proofs (the point of Tesl)

1. **Input proof — `TitleSafe title`.** The `NewTodo` codec runs `isSafeTitle`
   *while decoding JSON*. By the time `createTodo` sees `newTodo.title` it is
   proven within the allowed length; a bad title is rejected with `400` before
   any handler code runs.
2. **Output proof — `Todo ? FromDb (Id == todoId)`.** `getTodo` returns a row the
   SQL `select` boundary proved came from the database under the requested id.
   The `?` return spec threads that proof to the caller, so the response is
   type-level evidence of provenance — not a value a handler could fabricate.

## Run it

```sh
tesl db start     # provision the managed local PostgreSQL ([database].mode = "managed")
tesl build        # type-check + compile (proofs and the schema are enforced here)
tesl run          # serve on $PORT (default 8086)
                  # (build/run/test use [project].entrypoint — no file argument needed)

# in another shell — no session, so both are correctly rejected with 401:
curl -i -X POST localhost:8086/todos \
  -H 'content-type: application/json' -d '{"title":"Read the Tesl tutorial"}'
curl -i localhost:8086/todos/todo-1
```

## Authentication: what the scaffold does and does not ship

`app.tesl` ships the **verify** half of session auth: `JWT.verify` recomputes the
HMAC-SHA256 signature of the `session` cookie and rejects anything this service
did not mint. The user id is the `sub` claim, so it lives *inside* the signature —
which is what makes the `todo.ownerId != requestUser.id` ownership check in
`getTodo` mean anything.

**A bare `cookies "user"` check is not authentication.** The client chooses its own
cookies, so `curl -b 'user=anna'` would have impersonated anna and every ownership
check below it would have been decoration. The compiler reports that shape as
`SEC001` (`tesl help SEC001`); `tesl help manual best-practices#security` is the
full write-up. Never take a `role` or any other privilege from a cookie either —
put it in the signed claims, or look it up server-side from the verified user id.

The **mint** half is deliberately absent, because who may sign in is the one thing
no scaffold can guess. Add a login route that signs the claims:

```tesl
handler login(credentials: Credentials) -> String requires [appReadCookie, envRead] =
  # ... verify the credentials against your `user` entity, THEN:
  (JWT.sign (Dict.singleton "sub" credentials.user)
            (JwtSecret (requireEnv "SESSION_JWT_SECRET"))).value
```

`JWT.sign` sets the expiry itself (one hour, epoch seconds per RFC 7519), so the
capability wrapping `jwt` must also imply `time` — signing reads the clock. You
cannot choose the expiry, and putting an `exp` in the claims is an error rather
than an override: a caller who can choose an expiry can choose ten years. For a
credential that must outlive a session, use `Crypto.randomToken` and store only
its `Crypto.fingerprint`, which you can revoke.

Hand the returned string back as the `session` cookie. In the Tesl repository,
`example/learn/lesson57-jwt.tesl` walks through signing and verifying, and
`example/learn/lesson64-password-storage.tesl` covers checking the credentials.

Set `SESSION_JWT_SECRET` in `tesl.toml`'s `[env]` (there is a `CHANGE-ME` placeholder
there) — never in `app.tesl`, which is what `SEC003` reports.

## Tests

```sh
tesl test         # runs the `test "..."` blocks in app.tesl

# Run a single block by name; add --test-kind to disambiguate same-named
# blocks of different kinds (test | api-test | load-test | doctest):
tesl test --test-name "creates a todo" app.tesl
tesl test --test-name "POST /todos" --test-kind api-test app.tesl
```

`tesl build` compiles only, because `tesl.toml` says `[deploy].target = "local"`.
Set it to `"container"` (or run `tesl build --container`) to produce a Docker
image instead — see `tesl help manual deploy`.

To point at an existing database instead of the managed one, set
`[database].mode = "existing"` in `tesl.toml` and export the `TESL_POSTGRES_*`
variables yourself.
