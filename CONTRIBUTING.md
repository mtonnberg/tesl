# Contributing to Tesl

Contributions are welcome — Tesl is beta-stage and the interesting problems are all still open.

**This file routes; it does not teach.** The contributor content lives in
[`dev-docs/`](dev-docs/), and keeping the two separate is deliberate: a router cannot drift out of
sync with the guides the way a duplicated quick start can.

If you want to *write* Tesl applications rather than change the compiler, you are in the wrong file
— start at [`manual/GETTING-STARTED.md`](manual/GETTING-STARTED.md).

---

## 1. Get a working environment

```bash
git clone https://github.com/mtonnberg/tesl && cd tesl
nix develop            # or: direnv allow  (the repo ships a .envrc containing `use nix`)
cd compiler && dune build
```

The nix dev shell is the **only** supported environment — it pins Go 1.26, OCaml + dune and
PostgreSQL, and starts a project-local database. `dune build` produces
`compiler/_build/default/bin/main.exe`, which every script, test and editor integration expects.

Full setup, including `TESL_REPO_ROOT` (and why it is a trap in a git worktree), the PostgreSQL
scripts, and the first-hour gotchas:
→ **[`dev-docs/README.md`](dev-docs/README.md)**, "Quick start for a new contributor".

## 2. Run the gate

```bash
./ci.sh                  # from the repo root, inside the dev shell
```

**`./ci.sh` at the repo root is the authoritative gate.** It is the single command that decides
whether the tree is green.

Two things to know, because there are three names for one gate:

- **`compile-examples.sh` and `compiler/ci.sh` are thin shims** that `exec` into `./ci.sh`. They
  exist only so older hooks and muscle memory keep working. Run the real one.
- **`dune test` alone is not sufficient.** It misses the `tesl validate` sweep, byte-exact Go
  snapshots, corpus/runtime checks, and end-to-end gates. Passing `dune test` alone does not prove
  the tree green.

Run the full gate before you commit. For docs-only edits, `bash tests/doc-integrity.sh` is a
two-second standalone subset.

## 3. Read the guides

[`dev-docs/README.md`](dev-docs/README.md) first — it is the index, the environment setup, and the
"where to start, by task" table. Then the numbered guides for the layer you are touching: the parser,
the module system, the body compiler, the GDP proof runtime, the SQL layer, queues and pub/sub,
tests, and the frontend IR.

Never worked on this compiler before?
→ **[`dev-docs/12-your-first-compiler-change.md`](dev-docs/12-your-first-compiler-change.md)** walks
one real change end to end: where to edit, what breaks first, which snapshots regenerate, and what a
finished change looks like.

## 4. Pick something to work on

The roadmap is the queue:

| Folder | What it holds |
|---|---|
| [`roadmap/next/`](roadmap/next/) | actively being worked on — take a task from here |
| `roadmap/later/` | the backlog |
| [`roadmap/completed/`](roadmap/completed/) | the decision log: what was built, as built |
| `roadmap/discarded/` | **why not** — read this before re-proposing something |

When an item is done, move its file from `roadmap/next/` to `roadmap/completed/` **in the same commit
as the work**, rewritten to describe what was actually built rather than what was planned.

## 5. The workflow

Create a branch for your fix and open a PR.

Two house rules that are easy to miss:

- **Docs are single-sourced and partly contracted.** [`manual/anchors.md`](manual/anchors.md) lists
  anchors that compiler diagnostics cite as `<section>#<anchor>`, and the test suite fails if one
  stops resolving. Never rename or move an anchor-backed heading without migrating the anchor.
- **Generated files are promoted, not edited.** `compiler/lib/embedded_docs.ml` bakes `manual/` and
  `example/` into the binary and is regenerated by `dune build`. Edit the source and let dune
  re-promote it; commit the regenerated file alongside your change.

## 6. Reporting a bug

A `.tesl` file that reproduces it is worth more than a description. Include the diagnostic **code**
(`error[V001]`, `warning[W020]` — every diagnostic has a stable one) and, if the bug is that the
compiler *accepted* something it should not have, say so explicitly: soundness holes are the
highest-priority class of bug in this project.
