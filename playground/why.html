Why Tesl?

What can Tesl help you catch?

A backend has rules that ordinary types often leave to convention: this value was validated, this record belongs to this workspace, this function may write to a database. Tesl lets you express those requirements at the function boundary and checks the calls against them.

Choose a feature for the details, then try its example in the playground.

Make a missing check a compiler error

An invoice ID alone does not establish which workspace it belongs to. A function can require evidence for that particular invoice and workspace, and Tesl rejects a call that skips the check. The check itself still needs correct logic and tests.

See privileged operations in the signature

Capabilities make operations such as database reads and writes visible in function declarations. The requirement follows calls: if a helper writes to Note, its caller must declare dbWrite Note too. A read-only path cannot quietly gain a write through a helper. Authentication and the application's access policy still need to be designed correctly.

Use an API contract across server and clients

Declare routes and their types once, then generate TypeScript/Zod or Elm client code. The CLI also exports OpenAPI for tools that understand your HTTP contract. The playground’s generated-code view lets you inspect the client and Go output.

Keep money and measurements honest

Money values carry a currency and use exact integer minor units. Physical quantities carry dimensions, so adding a length to a duration is a compiler error. These types make mistakes visible that would look like ordinary arithmetic on raw numbers.

Build on the Go runtime

Tesl emits a Go project. You can inspect the generated application files and use the CLI to build and run them with the supplied Go runtime. The playground checks the source locally; it does not run the server.

Give people and coding agents useful feedback

Diagnostics have stable codes, source locations and, where available, edits the editor can apply. The CLI’s agent-context command gives a coding agent a compact view of errors and declarations, while targeted queries answer questions about types and symbols.

Where it fits today

Tesl is a beta language aimed at backend APIs. Start with a small project where you can evaluate its rules and tooling against your own needs. Expect changes while it develops; the repository and installation guide describe the current state.
